--- Harder evaluation 3: cross-dataset generalisation (train on one dataset, test on the other) ---
  train=base     -> test=phiusiil: precision=0.376 recall=0.809 f1=0.514 roc_auc=0.197
  train=phiusiil -> test=base    : precision=0.147 recall=0.999 f1=0.256 roc_auc=0.309
The cross-dataset ROC-AUC drops below 0.5, which shows there is big domain shift between the two datasets: 'not phishing' means different things in each (the base set has long defacement/malware URLs, PhiUSIIL's legitimate URLs are short and clean), so a model trained on one doesn't transfer to the other. This is why we train on both, and it's an honest sign that a single-dataset model wouldn't generalise to new data.

--- Documented limitations ---
1. URL-only analysis can't catch phishing on a plain new domain with no obvious clues - you'd need the page content or the domain age.
2. No timestamps in the data, so we can't do a proper time-based test; phishing changes over time so live results would be lower.
3. Labels come from two public datasets and have some noise. Combining two sources helps, but the cross-dataset test shows some shift remains.
4. Shorteners hide the real link - the model can only flag that a shortener was used, not where it goes.
