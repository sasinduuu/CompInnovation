## 1. Purpose

PhishGuard classifies a URL as **phishing** or **not phishing** using only the
URL string. It extracts 25 lexical and structural features, feeds them to a
trained gradient-boosted model, and returns a trust score together with the
specific suspicious components that triggered the decision. It is trained on
**two integrated public datasets** (Kaggle Malicious URLs + UCI PhiUSIIL) so it
generalises better and so cross-dataset shift can be measured.

The system is **fully offline**. It never resolves DNS, never issues a network
request and never fetches the target page — every feature is computed from the
URL text alone. This removes any risk of drive-by download or alerting the
attacker's infrastructure.

> **Important:** class 0 means *"not phishing"*, **not** *"safe"*. The
> non-phishing class still contains malware and defacement URLs, which are
> dangerous. The application never tells a user a URL is "safe".

## 5. Dataset preparation

The project uses two datasets:

1. **Base** — Kaggle *Malicious URLs Dataset* (`malicious_phish.csv`, ~651,000
   URLs labelled benign / defacement / phishing / malware).
   Source: https://www.kaggle.com/datasets/sid321axn/malicious-urls-dataset
   Place it at `data/raw/malicious_phish.csv`.
2. **Additional (integrated)** — UCI *PhiUSIIL Phishing URL Dataset*
   (Prasad & Chandra 2024, ~235,000 URLs labelled phishing / legitimate).
   Source: https://archive.ics.uci.edu/dataset/967/phiusiil+phishing+url+dataset
   A slim copy (URL + remapped label, gzipped) is already provided at
   `data/raw/phiusiil_urls.csv.gz`, so no extra download is needed to reproduce.

The included `data/processed/final_dataset.csv.gz` already holds the processed
features and labels used by the model (URLs omitted to keep the file small).
To regenerate the full processed dataset (including URLs, needed for the
cluster-example and error-analysis URL listings):

```bash
python src/data_prep.py
```

This cleans the data (removes duplicates, conflicting labels and empty URLs),
creates the binary `label`, extracts all 25 features, and writes
`data/processed/final_dataset.csv`.

## 7. Using the detector (application)

```bash
# Analyse one URL:
python src/predict.py "http://paypal.com.secure-login.tk/verify"

# Interactive prompt:
python src/predict.py

# Built-in demonstration set:
python src/predict.py --demo
```

**Example input / output**

```
$ python src/predict.py "http://192.168.10.5/wp-admin/appleid/verify.php"
====================================================================
URL analysed : http://192.168.10.5/wp-admin/appleid/verify.php
Phishing prob: 99.2%
Trust score  : 1/100
Verdict      : PHISHING   [HIGH RISK - LIKELY PHISHING]
Why:
   - uses a raw IP address instead of a domain name
   - substitutes digits/symbols for letters (e.g. paypa1 for paypal)
(The target page was never visited - analysis is 100% offline.)
====================================================================
```

Empty or malformed input is rejected with a clear message.

## 8. Model and results locations

* Trained model and threshold: `models/final_classifier.pkl`
* Feature scaler: `models/feature_pipeline.pkl`
* All figures, the model-comparison table and the evaluation report: `results/`

**Final model:** XGBoost with class weighting and a recall-oriented tuned
threshold, trained on the two combined datasets. On the held-out 20% test set:
**accuracy 0.934, phishing recall 0.820, phishing precision 0.876, F1 0.847,
ROC-AUC 0.974**. This replaces the original starter Random Forest, whose
phishing recall was only ~20%.

## 10. Known limitations

* URL-only analysis cannot catch phishing hosted on a plain, newly registered
  domain with no lexical giveaways; page content or domain age would be needed.
* The dataset has no timestamps, so a true time-based holdout is not possible;
  phishing patterns drift, so live accuracy will be lower than the test figure.
* Labels come from two public datasets and contain some noise (a few benign-
  labelled URLs are structurally indistinguishable from phishing).
* The two datasets show real domain shift (see the cross-dataset test in
  `evaluate.py`): a model trained on one does not transfer cleanly to the other,
  so deployment on a genuinely new source would need recalibration.
* Shorteners hide the true destination; the model can only flag that a
  shortener was used, not where it leads.

## 11. Offline confirmation

The entire project imports no HTTP or networking client. `features.py` works on
the URL string only, and `predict.py` prints a reminder with every verdict that
the target page was never visited. The application can be run with no internet
connection.

## 12. Reproducibility

All randomness is seeded (`RANDOM_SEED = 42` in `src/config.py`), so
`data_prep.py` → `train_models.py` reproduces the same split, model and metrics
on any machine. No paths are hard-coded; everything resolves relative to the
project root.
